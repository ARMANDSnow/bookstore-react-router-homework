## 建议的现场讲解顺序

1. **作业1**：打开完整Prompt和生成脚本 → 展示最终[OpenAPI JSON](../../backend/src/main/resources/static/api/v1/openapi.json) → 对照Controller四个操作 → 展示保存的5轮结果与响应校验。无需重新付费生成规范；已有截图和完整Prompt在[报告](提交/524031910745-作业1.docx)内。
2. **作业2**：前端 `/assistant` 选《微服务设计（第2版）》并问库存和价格 → 展开工具记录 → 沿Schema、解析、执行、回填讲一遍。用 `/assistant?scenario=competitor-timeout-once` 演示首次超时与模型同ISBN重试，错误ISBN可输入12345。
3. **作业3**：先展示政策原文、切块与向量检索 → 前端 `/guide` 问“推荐一本学习微服务的书，拆了塑封不喜欢还能退吗？” → 展开两步行动和政策依据。若服务未启动，按[作业3运行说明](作业3-运行说明.md)启动Embedding、后端和前端，当前仓库统一用JDK21。
4. **作业4**：按[作业4运行说明](作业4-运行说明.md)启动隔离服务 → 打开该服务的 `/assignment4.html` → 无Token401 → 登录 → 带Token200 → 看虚拟线程与Java版本。再讲过滤器为何每次验签、为什么不创建Session，最后展示并发验收。

## 答辩时准确说明的边界

- OpenAPI多轮检查证明核心约束稳定，不保证大模型逐字节重复输出。
- 库存来自数据库；竞价为明确模拟值。工具调用是模型提出请求，本地Java执行后才有结果。
- 政策检索是真实Embedding；书目搜索是关键词排序。公开Thought是一句行动目的，不能把它说成完整内部推理。
- JWT保护当前 `/api/secure/**`，完整仓库历史API仍公开；签名可防篡改，JWT载荷没有加密。随机签名密钥重启后改变，多实例要共享安全配置。
- 虚拟线程证据来自实际请求；64并发全部成功不是与平台线程比较得到的性能提升倍率。
- 当前源码与旧提交包有版本区别；本轮注释只更新仓库源码，已有DOCX/ZIP未重新生成。现场展示使用当前仓库；本机原target若残留同名主类，启动可显式指定 `-Dspring-boot.run.main-class=com.homework.bookstore.BookstoreBackendApplication`。
