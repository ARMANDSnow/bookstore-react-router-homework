# 3B：购书向导与双工具循环

`GuideAgentService`使用真实DeepSeek接口，提供且仅提供 `search_book_catalog` 与 `query_store_policy` 两个只读工具。导购历史与作业2库存/竞价助手独立，不包含其异常场景参数。

本店书目工具对主题、书名和作者等简短关键词做字面匹配，按标题/作者/简介命中排序，最多返回5本。它不是向量检索；政策工具则使用3A的真实中文Embedding检索，保留课程政策原文、片段编号、来源、版本与相似度。

流程为：用户问题 → 模型选择一个动作 → 白名单校验并执行 → 以对应tool_call_id回传Observation → 模型继续选择或生成自然语言回答。复合“微服务推荐与拆封退货”要求先查本店书目，再查政策，最后引用实际policy-N依据回答；单问会员或质量条款无需查询书籍。若模型一轮提交多个动作，每个tool_call_id都会收到明确的单动作限制反馈，本轮不执行工具，允许下一轮修正。

每次咨询最多4轮模型请求、6个公开步骤，同一工具和查询最多实际执行2次；批量拒绝和非法参数不消耗实际执行额度；同时最多2次咨询。参数只允许query与不超过100字的purpose。模型提供的purpose是一句可公开的行动目的，前端标记为Thought；不是隐藏思考过程，不读取或展示reasoning_content。日志、结构化步骤及页面都按Thought → Action → Observation展示。

模型只能推荐工具返回的本店书籍。后端在最终回答前检查本轮所需查询是否执行，政策结论需引用实际返回的片段编号；遗漏查询或编造编号会要求模型补查或修正，仍受轮数上限约束。政策结论需引用实际片段，遇到政策服务断开或暂无依据时说明未知，不能假装确认退货；课程退款、会员积分抵扣尚未实现。用户可查看书籍详情、政策原文和行动记录，也可另开新对话。

前端使用纯文本显示模型答复和检索原文，不执行其中的HTML。请求进行时禁用重复发送，新问题的历史只包含成功对话，失败后重试按原轮次替换，可重试较早的失败问题并保留后续轮次；重试仅使用该轮之前的成功历史，不重复插入用户问题。Enter发送、Shift+Enter换行，并保护输入法组合状态；离开页面会取消本地请求。

验收脚本：`node scripts/assignments/verify_shopping.mjs`，通过真实模型/MySQL/Embedding验证单查书、单查政策、复合顺序、质量例外、空书目与政策未覆盖，保留真实请求ID。桌面脚本 `verify_shopping_browser.mjs` 使用Ego任务空间检查网络错误重试、推荐卡、依据、完整行动记录和输入行为。后端测试包含工具结果ID匹配、白名单、多个动作反馈、政策中断、循环上限和非法历史。

已验证：2026-10-06，本地后端全部76项测试通过，前端生产构建通过；六类真实DeepSeek/MySQL/Embedding咨询、三种非法输入与书目只读检查通过。实际停掉Embedding服务后，模型收到POLICY_UNAVAILABLE并说明无法确认会员规则，未引用虚构条款；恢复后/status为ready。

桌面回归覆盖默认态、中文断网提示、两条失败问题后重试较早轮次、推荐卡、政策原文、两步完整公开行动记录、多行输入、图书详情跳转与开启新对话。截图保存原始浏览器画面。证据为evidence/3b-real-model.json、3b-policy-outage.json、3b-browser.json及3b-desktop-*.png；仅证明本地实际运行，不表示已部署上线，未进行手机比例测试。
